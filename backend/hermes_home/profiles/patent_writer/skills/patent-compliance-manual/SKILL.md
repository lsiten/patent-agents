# 专利申请文件规范

## 全文硬性规则

- 不得出现逐字稿时间戳、说话人、会议口语或 Markdown 标记。
- 发明名称默认不超过 25 字，必要时不超过 60 字。
- 摘要必须包含：专利名称、技术领域、简化技术方案、技术效果，且不超过 300 字。
- 技术领域必须具体，不得过上位，不得写成发明本身。
- 背景技术应基于检索报告中的真实现有技术，采用三段式：宏观现有技术、公开文献/论文/公开资料评述、一个待解决技术问题；不得泄露本发明方案。
- 背景技术必须点名引用至少两个检索报告 `confirmed_sources`、`web_evidence` 或 `non_patent_prior_art` 中的真实来源标题、论文号、公开资料名称或 URL，并说明这些来源未解决的具体问题；不得只写“公开技术”“相关研究”等泛称。
- 待申请的新专利通常没有本发明自己的公开号或申请号，禁止虚构专利号。检索报告提供真实专利文献时，写明国别、公开号或申请号；未检索到相关专利文献但有真实论文、公开网页或权威网站时，可引用这些可核验来源并客观评述。若专利库、论文和公开资料均无法补足必要背景，应把缺口反馈给 CEO，由 CEO 向用户明确索要所需论文、公开资料或技术背景。
- 发明内容必须包含技术问题、技术方案和有益效果，且三者一一对应。
- 具体实施方式必须充分公开，至少 2 个实施例，使用自然段和步骤编号，不使用 Markdown 标题。

## 权利要求硬性规则

- 权利要求书必须由独立权利要求和从属权利要求组成。
- 权利要求1只能由 3 步或 4 步组成。
- 独立权利要求1不得超过250字；每项从属权利要求不得超过200字。
- 权利要求中的每个分号 `；` 和句号 `。` 后必须换行。
- 从属权利要求只能引用在前权利要求。
- 方法权利要求、系统/装置权利要求、具体实施方式和附图必须互相对应。

## 附图硬性规则

- 涉及结构、系统、流程、空间关系、画面处理或模块协同时必须生成附图。
- 公司规范下默认规划不少于 4 幅附图。
- 摘要附图只能选取说明书附图中最具代表性的一幅。
- 每幅附图必须主题不同，不能只换标题复用同一内容。
- 附图说明不得出现重复图号或重复标题。
- 生成的附图必须在撰写阶段输出中展示，并在最终 DOCX 对应位置插入。
