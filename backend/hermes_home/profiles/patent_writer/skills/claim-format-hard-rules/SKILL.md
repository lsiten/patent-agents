# 权利要求硬格式

## 独权

权利要求1只能采用 3 步或 4 步：

```text
1. 一种……方法，其特征在于，包括：
S1，……；
S2，……；
S3，……。
```

或：

```text
1. 一种……方法，其特征在于，包括：
S1，……；
S2，……；
S3，……；
S4，……。
```

## 标点换行

- 每个 `；` 后必须换行。
- 每个 `。` 后必须换行。
- 不要把多个步骤挤在同一自然段。

## 从权

### 引用格式
- 从权必须写成“根据权利要求N所述的……，其特征在于，……”。
- N 必须小于当前权利要求编号。

### 递进引用规则
- 优先采用分层递进引用策略构建多层次保护网
- 权2直接引用权1
- 权3引用权2（同时隐含引用权1）
- 权4及以后可引用多条相关从权
- 避免全部从权都只引用权1

### 从权递进顺序
从权按以下顺序递进：
1. 核心细化：对独权中核心技术特征的直接限定
2. 参数/条件：具体参数范围、阈值条件、配置要求
3. 替代实现：同一技术特征的多种替代方案
4. 处理步骤：细化核心处理步骤的子步骤或算法逻辑
5. 组合特征：多个技术特征的协同组合方式
6. 结构细节：装置或系统的具体结构、布局、连接关系
7. 风险规避：针对潜在侵权风险的限定特征

### 从权内容要求
- 每条从权应包含具体的附加技术特征，避免过于简单或泛化
- 附加特征应描述清楚，包含参数范围、功能描述或结构关系
- 从权字数一般应在80至450字之间
- 从权不得只写“根据权利要求N所述的……，其特征在于，所述[特征]”而无实质性限定
