# 说明书撰写

撰写公开充分、完整的专利说明书。

## 说明书结构

1. **技术领域** - 明确发明所属技术领域
2. **背景技术** - 描述现有技术及其不足
3. **发明内容** - 技术问题、技术方案、有益效果
4. **附图说明** - 简要说明附图内容
5. **具体实施方式** - 详细描述实施例

## 撰写原则

- 说明书必须公开充分，使本领域技术人员能够实现
- 实施例要充分，覆盖权利要求的所有技术特征
- 技术术语要前后统一，定义清楚
- 结合检索分析报告，突出创新点，规避现有技术

## 内容必要性判断

所有专利均需要权利要求书、技术领域、背景技术、发明内容和说明书摘要。

条件性章节按发明类型判断：
- 发明涉及结构、装置、系统、流程、空间关系、多模块协同或显示画面处理流程时，需要附图说明和说明书附图。
- 纯方法/算法类发明如果文字已足够清楚，可以不生成说明书附图，但流程图有助于理解时应生成。
- 权利要求需要实施例支撑时，必须生成具体实施方式；如果发明内容已充分公开，可简化但不能空缺。
- 有实际附图且图1适合作为摘要附图时，最终 DOCX 可使用该图作为摘要附图。

## Agent 与工具边界

- `description_writer` 只提供章节约束、写作提示和结构信号。
- 技术领域、背景技术、发明内容、附图说明、具体实施方式和摘要正文必须由专利撰写 Agent 自行撰写。
- 不得把交底文件的聊天格式、时间戳、说话人姓名、寒暄或口语开场等沟通痕迹写入说明书正文。
- 不需要的章节不要输出空字符串或占位符；需要的章节必须写完整。

## 工具使用

- `description_writer` - 辅助生成说明书各部分内容
  - section_type: technical_field / background / summary / drawings / detailed

## 分步撰写流程

1. 分别调用 `description_writer` 获取 `technical_field`、`background`、`summary` 的章节约束。
2. 需要附图时，调用 `description_writer(section_type="drawings")` 获取附图说明约束。
3. 需要实施例时，调用 `description_writer(section_type="detailed")` 获取具体实施方式约束。
4. 由 Agent LLM 写出正式 `description` 字段，并保证术语与权利要求一致。
