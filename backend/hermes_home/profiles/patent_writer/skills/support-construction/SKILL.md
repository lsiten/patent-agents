# 支持关系构建

确保权利要求得到说明书的充分支持。

## 支持性要求

1. 权利要求中的每个技术特征都要在说明书中有对应描述
2. 说明书的实施例要能够支撑权利要求的保护范围
3. 上位概念要有足够的下位实施例支撑

## 检查要点

- 权利要求的技术特征 → 说明书有详细描述
- 独立权利要求的范围 → 实施例覆盖边界情况
- 从属权利要求的特征 → 说明书有对应实施例

## 工具使用

- `support_checker` - 检查权利要求与说明书的支持关系

## Agent 与工具边界

- `support_checker` 只提供术语覆盖、章节存在性和明显缺口信号。
- 是否充分公开、是否支持权利要求、是否需要补写实施例，必须由专利撰写 Agent 结合工具信号自行判断。
- 如果支持关系不足，优先补写说明书和实施例，而不是删除核心权利要求特征。

## 修正流程

1. 调用 `support_checker(claims="权利要求全文", description="说明书全文")`。
2. 对每个缺口判断应补写说明书、补充实施例、统一术语，还是调整权利要求层级。
3. 修改后保持 `claims`、`description`、`abstract` 和 `drawings` 一致。
