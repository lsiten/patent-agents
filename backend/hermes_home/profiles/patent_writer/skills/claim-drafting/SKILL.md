# 权利要求撰写

撰写保护范围合适、清楚、简要的权利要求书。

## 总体原则

- 权利要求书中尽量不要出现公式，需要时将公式放到说明书中
- 独立权利要求只保留解决核心技术问题所必须的特征
- 保持独立权利要求的概括性，细节放从属权利要求
- 权利要求书必须由独立权利要求和从属权利要求组成
- 权利要求1只能写成3步或4步
- 权利要求1不得超过250字；每一步只写必要技术特征，不写实施例细节、可选参数、具体算法族或效果描述
- 每个分号`；`和句号`。`后必须换行
- 如果发明名称、摘要、发明内容或保护范围写明“方法及系统”或包含系统保护主题，权利要求书必须同时包含方法独立权利要求和系统独立权利要求；系统独权用模块/单元承接权利要求1的方法步骤。若不写系统独权，则发明名称、摘要和发明内容都必须统一为只保护方法。
- 从属权利要求应充分展开，每条从权应包含具体的技术特征限定、参数范围或功能描述，不应过于简单或泛化

## 核心技术特征提炼

### 聚焦主要技术问题
- 判断技术内容要解决的主要技术问题
- 找出直接回应该问题的关键步骤
- 次要技术问题留给从属权利要求

### 避免特征冗余
- 不要把具体实施方式、参数阈值写入独立权利要求
- 避免指定具体算法名称（如"YOLO v8"、"BERT"）

### 步骤框架与数据流
以3或4个核心步骤构建框架：
- 串联关系：前序步骤的输出作为后序步骤的输入
- 并列关系：设置后续整合步骤将并列结果组合
- 不得写成5步及以上，也不得把多个步骤挤在同一句中

## "所述"使用规则
- 技术特征首次出现：直接陈述，不加"所述"
- 技术特征再次出现：必须加"所述"前缀
- 从属权利要求引用的前序权利要求中的技术特征，在从权中再次出现时必须加"所述"

## 从属权利要求分层递进策略

### 递进引用原则
- 优先采用递进式引用策略，构建多层次保护网
- 权2直接引用权1，对独立权利要求的某一技术特征进行直接限定
- 权3引用权2（同时隐含引用权1），在权2基础上进一步细化
- 权4及以后可引用多条相关从权，形成组合限定
- 避免全部从权都只引用权1，导致保护层次单一

### 分层保护结构示例
```text
1. 一种方法，包括：S1；S2；S3。
2. 根据权利要求1所述的方法，其特征在于，所述S1中的[特征A]具有[限定]。
3. 根据权利要求2所述的方法，其特征在于，所述[特征A]的[参数]为[范围]。
4. 根据权利要求1所述的方法，其特征在于，所述S2包括：子步骤1；子步骤2。
5. 根据权利要求4所述的方法，其特征在于，所述子步骤1采用[算法/方式]。
6. 根据权利要求1所述的方法，其特征在于，所述S1与所述S2通过[组合方式]协同工作。
```

## 从属权利要求分类撰写模式

### 参数细化型从权
- **用途**：限定具体数值范围、阈值条件、参数配置，提高权利要求的确定性
- **结构**：根据权利要求N所述的……，其特征在于，所述[技术特征]的[参数]为[范围/条件]；
- **示例**：根据权利要求1所述的心率检测方法，其特征在于，所述采样频率为10Hz至100Hz；所述光源发光强度为50至500流明。

### 替代实现型从权
- **用途**：提供同一技术特征的多种替代方案，扩大保护范围的覆盖度
- **结构**：根据权利要求N所述的……，其特征在于，所述[技术特征]包括[替代方案1]、[替代方案2]或[替代方案3]；
- **示例**：根据权利要求3所述的心率检测方法，其特征在于，所述光学传感器包括光电二极管、光电三极管或CMOS图像传感器。

### 处理步骤型从权
- **用途**：细化核心处理步骤的具体操作逻辑、算法流程或子步骤
- **结构**：根据权利要求N所述的……，其特征在于，所述[处理步骤]包括：[子步骤1]；[子步骤2]；[子步骤3]；
- **示例**：根据权利要求1所述的心率检测方法，其特征在于，所述对心率光信号进行处理包括：滤波去噪；峰值检测；信号归一化；心率计算。

### 组合特征型从权
- **用途**：将多个技术特征进行特定组合，形成协同效果或限定组合方式
- **结构**：根据权利要求N所述的……，其特征在于，所述[特征A]与所述[特征B]按照[组合方式]进行协同[处理/控制/操作]；
- **示例**：根据权利要求2所述的心率检测方法，其特征在于，所述运动状态信息与所述心率光信号采用加权融合算法进行联合处理。

### 结构细节型从权
- **用途**：补充装置或系统的具体结构、连接关系、布局方式或物理形态
- **结构**：根据权利要求N所述的……，其特征在于，所述[结构部件]以[布局方式]设置，且[连接关系/技术效果]；
- **示例**：根据权利要求8所述的智能手表，其特征在于，所述多个发光二极管以环形阵列方式均匀分布在传感器探头周围，相邻发光二极管之间的间距为2mm至5mm。

### 风险规避型从权
- **用途**：针对潜在侵权风险或新颖性缺陷，增加特定限定特征
- **结构**：根据权利要求N所述的……，其特征在于，所述[技术特征]进一步满足[限定条件]，以[技术效果]；
- **示例**：根据权利要求6所述的心率检测方法，其特征在于，所述运动状态信息由加速度计和陀螺仪共同获取，其中加速度计采样频率高于陀螺仪采样频率，以提高运动状态识别精度。

## 从属权利要求撰写要点

### 内容充实度要求
- 每条从属权利要求应包含至少一个具体的附加技术特征
- 附加特征应描述清楚，避免模糊表述
- 参数范围应合理且有技术意义
- 功能描述应与发明技术方案相关

### 引用关系规范
- 从属权利要求只能引用在前的权利要求（编号小于当前权利要求）
- 引用时应使用"根据权利要求N所述的……"格式
- 多项引用时，权利要求编号之间用"和"或"或"连接

### 从权字数合理范围
- 从属权利要求一般应在80至450字之间
- 过短（少于80字）可能意味着限定不够具体
- 过长（超过450字）可能意味着包含了过多实施例细节

## 工具使用
- `claim_drafter` - 获取权利要求结构、特征顺序、保护层级和撰写模式建议

## Agent 与工具边界

- `claim_drafter` 只提供骨架、约束、撰写模式和范例，不直接产出最终权利要求正文。
- 正式独立权利要求和从属权利要求必须由专利撰写 Agent 结合需求分析、检索报告和工具骨架自行撰写。
- 不得把工具输出原样复制为最终权利要求。

## 分步撰写流程

1. 调用 `claim_drafter(features="技术特征", protection_scope="保护范围")` 获取权利要求骨架。
2. 基于骨架确定独立权利要求的必要技术特征，排除实施例细节和非必要参数。
3. 按照参数细化→替代实现→处理步骤→组合特征→结构细节→风险规避的顺序，为每条从权选择合适的撰写模式。
4. 采用分层递进引用策略，构建多层次保护网（权2引权1，权3引权2，权4引权1或权3等）。
5. 若保护主题包含系统，在 `claims.dependent_claims` 中加入不依附权利要求1的系统独立权利要求，例如“10. 一种……系统，其特征在于，包括：……”，并在其后按需要设置系统从属权利要求；系统独权不计入权利要求1的3/4步要求。
6. 输出 `claims.independent_claim` 与 `claims.dependent_claims`，不得包含“待补充”“暂无”等占位内容。
7. 自检权利要求1是否为S1-S3或S1-S4结构；若不是，必须重写。
8. 自检每个分号和句号后是否换行；若不是，必须修正格式。
9. 自检权利要求1是否超过250字；若超过，必须压缩到250字以内，将可选实现和参数转移到从属权利要求。
10. 自检从属权利要求是否充分展开，是否采用了分层递进引用策略。
