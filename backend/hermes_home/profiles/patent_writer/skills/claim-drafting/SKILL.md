# 权利要求撰写

撰写保护范围合适、清楚、简要的权利要求书。

## 总体原则

- 权利要求书中尽量不要出现公式，需要时将公式放到说明书中
- 独立权利要求只保留解决核心技术问题所必须的特征
- 保持独立权利要求的概括性，细节放从属权利要求
- 权利要求书必须由独立权利要求和从属权利要求组成
- 权利要求1只能写成3步或4步
- 权利要求1不得超过250字；每一步只写必要技术特征，不写实施例细节、可选参数、具体算法族或效果描述
- 每个分号`；`和句号`。`后必须换行
- 如果发明名称、摘要、发明内容或保护范围写明“方法及系统”或包含系统保护主题，权利要求书必须同时包含方法独立权利要求和系统独立权利要求；系统独权用模块/单元承接权利要求1的方法步骤。若不写系统独权，则发明名称、摘要和发明内容都必须统一为只保护方法。

## 核心技术特征提炼

### 聚焦主要技术问题
- 判断技术内容要解决的主要技术问题
- 找出直接回应该问题的关键步骤
- 次要技术问题留给从属权利要求

### 避免特征冗余
- 不要把具体实施方式、参数阈值写入独立权利要求
- 避免指定具体算法名称（如"YOLO v8"、"BERT"）

### 步骤框架与数据流
以3或4个核心步骤构建框架：
- 串联关系：前序步骤的输出作为后序步骤的输入
- 并列关系：设置后续整合步骤将并列结果组合
- 不得写成5步及以上，也不得把多个步骤挤在同一句中

## "所述"使用规则
- 技术特征首次出现：直接陈述，不加"所述"
- 技术特征再次出现：必须加"所述"前缀

## 工具使用
- `claim_drafter` - 获取权利要求结构、特征顺序和保护层级建议

## Agent 与工具边界

- `claim_drafter` 只提供骨架和约束，不直接产出最终权利要求正文。
- 正式独立权利要求和从属权利要求必须由专利撰写 Agent 结合需求分析、检索报告和工具骨架自行撰写。
- 不得把工具输出原样复制为最终权利要求。

## 分步撰写流程

1. 调用 `claim_drafter(features="技术特征", protection_scope="保护范围")` 获取权利要求骨架。
2. 基于骨架确定独立权利要求的必要技术特征，排除实施例细节和非必要参数。
3. 用从属权利要求承接可选参数、替代实现、界面/流程/模块细节和风险规避特征。
4. 若保护主题包含系统，在 `claims.dependent_claims` 中加入不依附权利要求1的系统独立权利要求，例如“10. 一种……系统，其特征在于，包括：……”，并在其后按需要设置系统从属权利要求；系统独权不计入权利要求1的3/4步要求。
5. 输出 `claims.independent_claim` 与 `claims.dependent_claims`，不得包含“待补充”“暂无”等占位内容。
6. 自检权利要求1是否为S1-S3或S1-S4结构；若不是，必须重写。
7. 自检每个分号和句号后是否换行；若不是，必须修正格式。
8. 自检权利要求1是否超过250字；若超过，必须压缩到250字以内，将可选实现和参数转移到从属权利要求。
