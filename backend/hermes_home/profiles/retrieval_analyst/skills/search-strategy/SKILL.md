# 检索策略制定

设计高效的专利检索关键词和分类号组合。

## 策略要素

1. **关键词选择** - 核心技术词、同义词、上下位词
2. **分类号组合** - IPC/CPC 分类号
3. **数据源选择** - 当前系统已配置、真实支持且可核验的数据源。专利库未配置时跳过；论文源和公开资料源可用于补强现有技术背景。

## 检索式构建

- 使用布尔运算符（AND、OR、NOT）
- 组合多个检索维度
- 逐步细化检索范围

## 工具使用

- `patent_search` - 执行已配置数据源检索
  - query: 检索关键词或技术描述
  - sources: google_patents,uspto,arxiv；只填写当前系统已配置/启用的数据源，留空则由工具使用全部已启用真实源
  - limit: 最大结果数量

## Agent 与工具边界

- `patent_search` 负责连接真实专利数据源并返回可核验证据；检索式设计、关键词取舍、数据库优先级和补检策略由检索分析 Agent 判断。
- 默认中国申请时，优先使用当前系统已配置且可核验的数据源；未配置的数据源不能调用，必须记录为未启用/未配置并跳过。如果已配置专利源不可用或无结果，必须记录为数据源覆盖限制，并改用论文源、官方或专业公开来源继续补检。本机未配置某个来源不能单独作为需求缺口或流程终止理由。
- 数据源超时、未接入或无结果时，必须如实记录证据缺口，不得虚构专利号、申请人或公开日。
- `databases_used` 只能记录已有真实返回证据或已成功读取证据的数据源；请求过但无结果、未接入、超时或无法验证的数据源要写入 `unavailable_sources` 或 `evidence_gaps`。
- 无结果不是终止条件。必须分析无结果原因，并至少尝试中文宽检索、英文宽检索、核心区别特征窄检索三类补检；每轮基于上一轮返回或失败信息调整检索式。专利源无结果后转论文源；论文源不足后转公开网页/权威网站；仍不足时基于可靠信息、公开工程常识、真实世界物理规律和本领域普通技术人员知识进行可实施性推理。
- 只有可靠证据和合理工程推理仍不足以支撑完整方案时，才让 CEO 向用户补充信息，并必须给出明确资料类型，例如“请补充某论文/产品资料/实验参数/机构结构说明”，不能泛泛要求补充。
- 公开网页或 Google Patents 候选证据必须用专业信息网站、专利详情页、专利局页面、标准组织或官方资料交叉确认真伪。
- 需要网页证据时，先完成专利检索主链路，再按 `web-evidence-strategy` 补充。
